Relational vs non-relational dbs

Relational db:
Data stored in tables (rows & columns)
Fixed schema (structured)
Uses SQL
Supports joins and strong relationships
Ensures ACID properties (high consistency)

👉 Examples: MySQL, PostgreSQL, Oracle Database

👉 Use when:

Data is structured (banking, transactions)
You need accuracy & consistency

Non-relational db: 
Data stored as JSON, key-value, documents, or graphs
Flexible schema (semi/unstructured)
No strict table relationships
Designed for scalability & performance

👉 Examples: MongoDB, Cassandra, Redis

👉 Use when:

Data is large, fast-changing, or unstructured
Need high scalability (big data, real-time apps)
